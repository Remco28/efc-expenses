### [MEDIUM] A reload that finishes after a tab change paints the previous tab

File: `public/app.js:227`. Scenario: On a slow phone, save trip details (or tick a payment, or finalize). `refresh("families")` or `refresh("treasurer")` is in flight. Before it returns, tap another tab of the same trip, such as Expenses or "How was this worked out?" (`#/t/<id>?tab=settle&open=<family>`). That navigation used to bump `routeSeq`, and `refresh` refused to draw when the sequence had moved on. It now treats every `#/t/<id>` URL as the same screen, ignoring the query. Wrong outcome: Whichever request finishes last wins. The in-flight `refresh` calls `renderTrip` with the tab it started with, so the Families or Treasurer tab replaces the one just opened, and an older `S.trip` can replace a newer load. Switch tabs again to get back. Suggested fix: Capture `routeSeq` or the full hash, including the query, before the fetch, and skip `renderTrip` if either has changed.
